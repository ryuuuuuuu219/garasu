# 弱点残存時にクラック進展が停止する現象

記録日: 2026-07-28

## 確認された現象

- 弱点が破片内に残っている。
- その状態で着弾しても、クラック処理が進まない。

## 調査観点

1. 破片化後の弱点ノードと `EnemyDefeatComponent` の引き継ぎ
2. 表面傷から成長可能な候補が残っているか
3. 外周平行候補の拒否閾値 `0.01` が小さい破片で候補を過剰除外していないか
4. 走査半径、必要破砕コスト、プール衝撃エネルギーの関係
5. クラック進展失敗時の小破片解放処理

## 暫定解析結果

最有力原因は「分割線上に残った弱点が、新しい外周上のノードになっていること」。

### 発生経路

1. クラックでポリゴンを分割する。
2. 弱点が分割線上にあると、`IsPointInsideOrOnPolygon` により両方の領域で弱点を含むと判定される。
3. 両方が弱点を含む場合、面積が大きい側を元の敵Objectとして残す。
4. 元Objectへ残した弱点は `RetainFragment` によって `initCrackPoint` に維持される。
5. 分割線は残存破片の新しい外周になるため、弱点も外周上に残る。
6. 新しい着弾点が同じ外周辺上にある場合、表面傷から弱点への候補は
   `surfaceParallelRejectionDistance = 0.01` の外周追従防止判定で拒否される。
7. 候補に使われなかった衝撃エネルギーは `pooledImpactEnergy` に返る。
8. ただし生存中の弱点を持つ破片は、進展失敗時の終端破片解放処理から除外される。
9. 他に有効な内部点・クラック先端がなければ、エネルギーだけが蓄積してクラックが永久に進展しない。

### この形状との関係

左辺 `x ≈ 0.0982593` は長いほぼ完全な直線であり、過去の分割線が新しい外周になった可能性が高い。
弱点座標のxがこの値に近く、yが `-0.3258312～0.4730277` 内なら、この停止経路と一致する。

距離確認式:

```text
abs(weakPoint.x - 0.098259325) <= 0.01
かつ
-0.3258312 <= weakPoint.y <= 0.4730277
```

### 補足

- 外周平行候補を拒否する処理自体は意図どおり。
- 問題の本体は、弱点を「分割線上のまま生存側へ残す」ことと、
  「弱点生存中は進展失敗時の解放を禁止する」ことの組み合わせ。
- `pooledImpactEnergy` が増えても、候補が幾何判定で0件ならエネルギー量では解消しない。

## 弱点への直接進展が止まる原因の確定

弱点座標:

```text
(0.2366643, -0.423734933)
```

これは対象外形の頂点インデックス3と完全一致する。

```text
outline[3] = (0.2366643, -0.423734933)
```

したがって弱点は内部点ではなく、現在の外周頂点そのものになっている。

この頂点に接する外周辺:

```text
edge 2: outline[2] → outline[3]
edge 3: outline[3] → outline[4]
```

`edge 2` または `edge 3` 上に表面傷がある場合、接続先である弱点は同じ辺上にある。
接続先から辺までの距離は0なので、`surfaceParallelRejectionDistance = 0.01`
の判定により必ず拒否される。

また、この弱点は頂点ノードなので脆弱性0となる。別の辺から弱点へ向かう候補は
外周平行判定を通過できる可能性があるが、脆弱性によるコスト軽減はない。

### 確定した弱点直接候補の停止条件

1. 残存内部点は弱点1点だけ。
2. その弱点が外周頂点と一致している。
3. 弱点に隣接する辺へ着弾すると、唯一の通常接続先が外周追従候補として拒否される。
4. 候補不成立なので衝撃エネルギーはプールへ戻る。
5. 幾何判定による拒否はエネルギー量で解除されない。
6. 生存弱点があるため、進展失敗時の終端破片解放も実行されない。

以上により、隣接辺から弱点へ直接進む候補は必ず停止する。

### 全クラック停止について残る確認点

通常の内部候補が0件でも、コード上は弾の進行方向と外周の交点を使う
「エネルギー付き外周フォールバック」を追加できる。このフォールバックまで成立しない理由は、
外形と弱点座標だけではまだ確定できない。

次のいずれかを追加確認する必要がある。

- 着弾ローカル座標
- `BulletStatus.CurrentVelocity`
- 1発分の `newImpactEnergy`
- `pooledImpactEnergy`
- `scanRadius`
- Gizmo上の青い一次候補、赤い拒否候補、緑の採用線

特に、弾の進行方向がガラス内部を横切らず外側または外周接線方向を向いている場合、
外周フォールバック交点が生成されず、全候補0件のままになる。

5発を超えても一切進展しない場合、次を疑う。

1. 既存クラック接続があり、開始点が着弾頂点ではなく別の「最遠内部先端」へ切り替わっている。
2. その先端の基準方向が外向きになり、外周フォールバック交点を取得できない。
3. 分割・再初期化などにより `pooledImpactEnergy` が0へ戻っている。
4. 候補が別経路へ少量ずつ採用され、見かけ上進展せずプールも全量残っていない。

## 弱点が次数2にならず分割線上へ残る経路

通常の永続グラフだけで外周から弱点を経由して別外周まで接続すれば、
弱点ノードの次数は2になり、分離処理前の `EvaluateWeakPointDefeat` で撃破される。

ただし現行処理には、グラフ接続を追加しない分離専用補完がある。

### 処理順

```text
1. ApplyCrackPathsWithinBudget
   永続的な crackConnections を追加

2. EvaluateWeakPointDefeat
   この時点の crackConnections だけで弱点次数を数える

3. BuildRenderableCrackPaths

4. TrySeparateCompletedPath
   必要なら TryCompleteNearBoundaryPath を実行
```

`TryCompleteNearBoundaryPath` は次数1の内部先端から最寄り外周までの距離が
`boundaryCompletionDistance` 以下なら、次の一時パスを作る。

```text
既存の外周 → ... → 次数1の先端 → 最寄り外周点
```

しかし最後の「先端→最寄り外周点」は以下を行わない。

```text
- GetOrCreateNode
- AddConnection
- EvaluateWeakPointDefeat
```

一時的な `completedPath` 配列へ外周点を追加し、そのまま
`TrySeparateAlongCrack` へ渡すだけ。

したがって、その次数1先端が弱点だった場合:

```text
グラフ上: 外周 → 弱点
          弱点次数 = 1

分離用形状: 外周 → 弱点 → 補完外周点
            外周同士を結ぶのでポリゴン分割可能
```

弱点は未撃破のまま分割線の構成点になり、残存破片の新しい外周頂点になり得る。

一度弱点が新外周上へ出ると、既存の「外周→弱点」だけでも描画パスの両端が
外周上になるため、以後も弱点次数1のまま分離条件を満たせる。

### 結論

弱点からの接続数が2にならない理由は、分割成立に使われた最後の外周補完線分が
`crackConnections` に登録されていないため。

これは弱点撃破判定と分離判定が異なるデータを見ていることによる不整合。

### 「弱点が始点にならない」の区別

着弾時の表面根元 `surfaceFlaw` は必ず外周側に作られる。
ただし候補生成へ渡す `startNode` は常に表面根元とは限らない。

`FindCrackTipFromSurfaceRootOrFallback` は、表面根元につながる成分を探索し、
次数1の内部先端のうち根元から最も遠いノードを返す。

したがって次の状態では:

```text
外周根元 ── 弱点
              次数1・内部先端
```

次回着弾時の候補生成開始点は弱点になり得る。

ただし、ここから通常のエネルギー付き外周フォールバックが成立した場合は:

```text
外周根元 ── 弱点 ── 外周フォールバック
```

両方が正式な `crackConnections` なので、分離前の弱点評価で次数2となり撃破される。

同じ着弾内で一次接続「外周→弱点」と二次外周フォールバック
「弱点→外周」が同時採用された場合も、両接続追加後に弱点評価されるため撃破される。

生存したまま分割できる例外は、正式接続を追加しない
`TryCompleteNearBoundaryPath` の一時補完。

この補完が要求する前提も指摘どおりであり、
`TryFindShortestBoundaryPathToNode` によって既存の「外周→弱点」経路が必要。

```text
既存グラフ: 外周 → 弱点（次数1）
一時補完:            弱点 → 外周
```

後半だけがグラフへ登録されないため、形状上は外周同士を結んでも弱点次数は1のまま。

## A–C線分が途中の弱点Bを飛び越す可能性

コード構造上は可能。

`TryBuildCandidate(A, C)` は次を確認する。

```text
- AとCが同じノードではない
- A–Cが既存の直接接続ではない
- 距離が走査範囲内
- Cがポリゴン内または外周上
- A–Cが途中で外周を横切らない
- A–Cが既存クラック辺と不正交差しない
```

一方、次は確認しない。

```text
- A–C線分の途中に別のCrackNode Bがあるか
- そのBが弱点か
- A–CをA–BとB–Cへ分割すべきか
```

したがってBがA–C上にあっても、グラフにはA–Cが1本追加されるだけ。

```text
幾何:
A ─── B ─── C

グラフ:
A ───────── C
Bは未接続、または別接続1本だけ
```

このA–Cを含む外周間パスで分割すれば、Bは幾何学上の分割線上に存在しても
弱点次数は増えない。

### 現在のoutline配列との注意点

A–CパスにBが明示点として含まれていなければ、`TrySplitPolygon` が作る新領域にも
Bは頂点として追加されない。BはA–C外周辺の途中に乗るだけ。

現在の `outline[]` にはB座標が明示的な頂点として存在するため、
A–Cによる1回の分割だけでは現在状態を完全には説明できない。

Bが明示頂点になるには、その後さらに次のいずれかが必要。

```text
- 後続クラックの端点がBになった
- 後続分割の外周交点がBになった
- 実際にはAまたはCがBだった
```

### 既定シードの初期内部点による共線性

難易度8で使われ得る最大40個の初期点について、弱点Bを除く全ペアを検査した。

Bに最も近い線分:

```text
A = 生成点18
  (-3.7591717205, 0.1114916497)

C = 生成点38
  (3.4074200762, -0.8550128873)

BからA–Cへの距離
= 0.0036290263
```

幾何許容値:

```text
GeometryEpsilon = 0.0001
```

最短でも許容値の約36倍離れている。したがって、既定シードの初期内部点同士だけで
A–Cが弱点Bを正確に通る組合せはない。

ただしA/Cのどちらかが後から生成されたクラック先端、交点、外周フォールバック点なら
この検査対象外であり、B飛び越し経路は依然として成立し得る。

## 対応: 一時外周補完の完全廃止

`TryCompleteNearBoundaryPath` と関連設定・候補型・補助探索を削除した。

分割条件は次の正式な経路だけになった。

```text
- 描画クラックの両端が外周上
- crackConnections上で異なる外周ノード同士が接続済み
```

次数1の内部先端から外周までの距離が短くても、分離専用座標を追加しない。
外周へ到達するには、エネルギーを消費する通常候補または通常の
外周フォールバックが正式なノード・接続を生成する必要がある。

これに伴い、次の設定と診断イベントは廃止した。

```text
boundaryCompletionDistance
maxBoundaryCompletionCandidates
TEMPORARY_BOUNDARY_COMPLETION
TEMPORARY_COMPLETION_FROM_WEAKPOINT
```

## 脆弱性ルール変更

ノードの役割ごとの脆弱性を次へ統一した。

```text
弱点                        = 0.1
着弾点・表面傷              = 0
内部点                      = 入力乱数を0.5～1へ写像
通常の外周辺上の点          = 0
通常の外周頂点              = 0
外周フォールバック点        = 1
```

役割が重なる場合は弱点を優先する。したがって、分割などにより弱点が外周または
頂点へ移動した場合も弱点脆弱性`0.1`を維持する。通常の外周フォールバックが
既存の弱点座標へ一致した場合も同様。
